# CubeMX Regeneration Notes

This project is generated by STM32CubeMX / STM32 Project Generator and then adjusted by hand. When regenerating code from `fsbl_appli_led_usart_baseline.ioc`, keep the notes below in mind.

## Usually Preserved

CubeMX normally preserves code placed between matching `USER CODE BEGIN ...` and `USER CODE END ...` markers.

Important user code currently protected this way:

- `FSBL/Core/Src/main.c`
  - Includes `extmem.h`.
  - Calls `MX_EXTMEM_Init()`.
  - Calls `BOOT_Application()`.
- `FSBL/Core/Src/extmem.c`
  - Includes `extmem.h`.
  - Defines SigningTool header constants.
  - Implements `MX_EXTMEM_Init()`.
  - Implements `BOOT_GetApplicationSize()`.
- `FSBL/Core/Inc/extmem.h`
  - Includes `stm32_extmem_conf.h`.
  - Declares `MX_EXTMEM_Init()`.
- `FSBL/Core/Inc/stm32_extmem_conf.h`
  - Contains the EXTMEM/LRUN configuration for loading Appli from XSPI2 external flash to internal RAM.
- `Appli/Core/Src/main.c`
  - Defines `App_Print()`.
  - Defines `Baseline_DelayMs()`.
  - Prints startup and heartbeat messages over USART3.
  - Toggles the board LED every second.

## High-Risk Files

These files can be overwritten or reverted by CubeMX / Project Generator because they are generated project files or custom files that CubeMX may not understand fully.

- `Makefile/FSBL/Makefile`
  - The middleware paths were changed to use the project-local path:
    - `../../Middlewares/ST/STM32_ExtMem_Manager`
  - CubeMX may regenerate the previous path:
    - `../../../../Middlewares/ST/STM32_ExtMem_Manager`
  - If FSBL build fails with `stm32_extmem.h: No such file or directory`, check this file first.
- `.vscode/c_cpp_properties.json`
  - Contains separate `FSBL` and `Appli` IntelliSense configurations to avoid `main.h` name collision.
  - FSBL must list `FSBL/Core/Inc` before `Appli/Core/Inc`.
- `.vscode/settings.json`
  - Contains local tool paths for this machine.
- `.vscode/tasks.json`
  - Contains build, sign, flash, and RAM-run tasks.
  - `Flash: BootChain EXT (FSBL->Appli)` is intentionally in the `build` group so it appears from `Ctrl+Shift+B`.

## After Regenerating From CubeMX

Run these checks before flashing:

```powershell
D:/gunwin32/gnuwin32/bin/make.exe -C Makefile/FSBL
D:/gunwin32/gnuwin32/bin/make.exe -C Makefile/Appli
```

If FSBL fails to build, check:

- `Makefile/FSBL/Makefile` still uses `../../Middlewares/ST/STM32_ExtMem_Manager`.
- `FSBL/Core/Src/main.c` still includes `extmem.h` and calls `MX_EXTMEM_Init()` before `BOOT_Application()`.
- `FSBL/Core/Src/extmem.c` still defines `BOOT_GetApplicationSize()`.
- `FSBL/Core/Inc/stm32_extmem_conf.h` still has:
  - `EXTMEM_LRUN_DESTINATION_ADDRESS 0x34000000U`
  - `EXTMEM_LRUN_SOURCE_ADDRESS 0x00100000U`
  - `EXTMEM_HEADER_OFFSET 0x400U`

## Recommended Workflow

Before opening or regenerating with CubeMX:

```powershell
git status
git commit -am "Save work before CubeMX regeneration"
```

After CubeMX regeneration:

```powershell
git diff
```

Review the high-risk files above carefully, then rebuild FSBL and Appli.
